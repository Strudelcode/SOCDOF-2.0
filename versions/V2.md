# SOCDOF Version 2 Technical Log

## v2.0.0 - 2026-08-25

### Changes

- Established the SOCDOF 2.0 major release line in alignment with the application branding.
- Corrected the WPF code-behind compilation failures by importing `System.ComponentModel` wherever `ICollectionView` is used.
- Corrected the project item declarations so all resources and optional application-icon references are contained inside valid MSBuild groups.
- Added the multi-page documentation site with dedicated start, features, and local API pages.
- Synchronized the application and project version metadata to `2.0.0` / `v2.0.0`.
- Added workflow rules for classifying major release tags as full releases and subsequent minor or patch tags as pre-releases.
- Set the published executable name to `SOCDOF_2.0.exe` and added Publisher, Product, and Description assembly metadata.
- Added optional `app.ico` resource packaging with a safe `logo.png` fallback for the WPF window.
- Added a tag-only Inno Setup path that produces `SOCDOF_setup.exe` without affecting normal CI build speed.

### Asset Handling

- `src/Assets/logo.png` and `src/Assets/app.ico` are optional project assets.
- The WPF window attempts to load the PNG at runtime and continues without it when unavailable.
- `<ApplicationIcon>` is emitted only when a valid ICO file exists, because MSBuild does not accept PNG files as application icons.
- No placeholder or fabricated image data is generated.

### Build Verification

- `git diff --check`: Passed.
- `dotnet build`: Not runnable in the current workspace because the `dotnet` command is unavailable; GitHub Actions remains the required CI verification.
- `dotnet publish -c Release`: Not runnable in the current workspace for the same missing-SDK reason; the Windows runner performs the publish verification.
- Inno Setup compilation: Configured in GitHub Actions for tagged Windows releases; local verification requires `iscc`.
