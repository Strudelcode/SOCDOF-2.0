# SOCDOF Version 2 Technical Log

## v2.0.2 - 2026-08-26

### Changes

- Added automatic SemVer tag creation after a successful `main` branch build, reading the active version from `AppConfig.cs`.
- Prevented tag mutation: an existing version tag must already point to the current commit or the workflow fails with an explicit version-bump message.
- Reused the dynamic major-version release-notes resolution and publishes `vX.0.0` as a full release while classifying other `vX.Y.Z` tags as pre-releases.
- Added a dependency-free Node preview server with `npm run dev -- -p 3000 -H 0.0.0.0` support.
- Switched tagged release distribution to the Inno Setup package only; the portable executable is no longer uploaded or offered as a release asset.
- Enabled free installation-directory selection with the default `{autopf}\\SOCDOF 2.0` path, Start menu and optional desktop shortcuts, and the standard uninstaller.

## v2.0.1 - 2026-08-26

## v2.0.0 - 2026-08-25

### Changes

- Established the SOCDOF 2.0 major release line in alignment with the application branding.
- Corrected the WPF code-behind compilation failures by importing `System.ComponentModel` wherever `ICollectionView` is used.
- Corrected the project item declarations so all resources and optional application-icon references are contained inside valid MSBuild groups.
- Added the multi-page documentation site with dedicated start, features, and local API pages.
- Synchronized the application and project version metadata to `2.0.0` / `v2.0.0`.
- Added workflow rules for classifying major release tags as full releases and subsequent minor or patch tags as pre-releases.
- Set the published executable name to `SOCDOF_2.0.exe` and added Publisher, Product, and Description assembly metadata.
- Added optional `app.ico` resource packaging with a safe `logo.png` fallback for the WPF window.
- Added a tag-only Inno Setup path that produces `SOCDOF_setup.exe` without affecting normal CI build speed.

### Asset Handling

- `src/Assets/socdof_v2_icon.ico` and `src/Assets/socdof_v2_icon.png` are optional project assets.
- The WPF window attempts to load the ICO first and the PNG as a visual fallback, continuing without either when unavailable.
- `<ApplicationIcon>` points to the uploaded ICO only when it exists; PNG remains a UI fallback because MSBuild requires a real ICO for application icons.
- No placeholder or fabricated image data is generated.
